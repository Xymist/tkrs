# Optimize blocked command: focused blockers

How: reuse ready metadata, display only open blockers, and share the common sorter; Why: avoid duplicate parsing and improve signal-to-noise.

## Implementation plan
- Reuse the shared ticket metadata map (as in ready/ls) to avoid multiple reads; filter tickets with status open/in_progress only.
- Compute blockers by checking deps against the map and keeping only those whose status is not `closed`; ignore missing deps or flag them explicitly.
- Sort with the same priority+id comparator as `ready` for consistent display; consider a `--only-open`/`--status` filter to hide in-progress blockers.
- Add tests for open-only blockers, missing deps handling, and order stability.
