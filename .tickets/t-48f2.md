# Optimize close command: consistent closure metadata

How: add closed-at timestamp and optional close note via status helper; Why: improve traceability and avoid repeated file writes.

## Implementation plan

- Extend the status helper (shared with start/reopen) to support a `closed_at` timestamp field in frontmatter when transitioning to `closed`; avoid touching `created`.
- Allow `close` to accept an optional message/note flag that appends a timestamped note about closure reason in the Notes section.
- Ensure the write is single-pass: update frontmatter and append note (if any) in one write to avoid multiple fs hits.
- Add tests for closed-at presence, note append, and idempotent close when already closed.
