# Pushing a new version to Github should generate a binary release

## Need

We need a GitHub Actions workflow that, when a tag matching the semantic version pattern `vX.Y.Z` is pushed, automatically builds the Rust binary and publishes a binary package for that version in the repository.

## Acceptance Criteria

- A GitHub Actions workflow triggers on tags matching `v*.*.*` and ignores other pushes.
- The workflow builds the Rust project in release mode on a Linux runner.
- The workflow produces a versioned binary artifact named with the tag (e.g., `ticket-v1.2.3-x86_64-unknown-linux-gnu.tar.gz`) and uploads it as a release asset or workflow artifact.
- The workflow fails the job if the build or packaging step fails.
- Documentation in README or docs notes how the release workflow is invoked and what artifact it produces.

## Notes

- Added `.github/workflows/release.yml` triggering on `v*.*.*` tags to build the release binary, package it, and publish a GitHub release with the tarball asset. Artifact name: `ticket-${tag}-x86_64-unknown-linux-gnu.tar.gz`.
- README documents the release workflow behavior.
