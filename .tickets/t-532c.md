# Optimize ls command: stable sort & filters

How: move to consistent sorting, add --columns/--json flags, and reuse metadata parser; Why: reduce repeated sorts and make output more controllable.

## Implementation plan

- Refactor `cmd_ls` to reuse the shared ticket metadata reader once, then sort with a stable comparator (priority, id) using iterators instead of repeated sorts.
- Add `--columns` flag to select displayed fields (e.g., `id,status,title,deps`) and `--json` flag to emit structured rows; default stays the current human view.
- Ensure tags/status filtering uses shared `ticket_matches_filters`; avoid rebuilding strings for deps when not requested.
- Add tests for column selection, JSON output shape, and stable ordering on same-priority items.

## Changes made

- Refactored `ls` to sort by priority then id, reuse shared filters, and support `--columns` plus `--json` output.
- Added CLI tests covering columns selection, JSON output, and stable ordering.
- Documented new flags in README.
