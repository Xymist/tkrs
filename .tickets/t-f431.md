# Optimize reopen command: fast reopen with logging

How: centralize reopen flow with the status helper plus optional reason note; Why: dedupe code paths and record why items re-open.

## Implementation plan

- Route `reopen` through the shared status helper to update status and optionally append a timestamped note describing the reopen reason.
- Guard against reopening already-open tickets unless a note is provided; avoid double writes if no change.
- Ensure any `closed_at` field is cleared/removed when reopening to keep metadata accurate.
- Add tests for reopen with/without reason, closed_at removal, and idempotent behavior.

## Notes

- `reopen` now uses the shared status helper, clears any `closed_at`, and supports `--note` to log reasons.
- Added regression test for closed_at removal, optional note, and idempotent reopen.
