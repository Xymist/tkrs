# Non-interactive body set/update for existing tickets

Agents cannot update a ticket body after creation: tk edit launches $EDITOR and blocks, add-note only appends timestamped notes, and the section flags (-d, --implementation-plan, --acceptance, --body-from-file) exist only on tk create. Provide a non-interactive path to set or replace body content on an existing ticket.

## Implementation Plan

Options: extend tk edit with the same section flags create has (-d/--description, --implementation-plan, --acceptance, --body-from-file), skipping the editor when any is passed; or add a dedicated subcommand (e.g. tk set/update). Prefer reusing the create flag names for consistency. Decide replace-vs-append semantics per section and preserve the always-present-headings round-trip guarantee from tic-3415f.

## Acceptance Criteria

A ticket body section (description, implementation plan, acceptance criteria) can be set or replaced from the command line or a file with no TTY and no $EDITOR; unspecified sections are untouched; all headings still round-trip; help text documents the semantics.
